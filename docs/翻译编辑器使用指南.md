# DoL / DoLP Kit 翻译编辑器使用指南

[返回仓库首页](../README.md) · [下载 HTML 编辑器](../dolp-kit-translation-editor.html) · [English](KIT-EDITOR-GUIDE.en.md)

这是为 **Toolkit 导出的 localization Kit** 准备的离线可视化编辑器。
只提供一个 `dolp-kit-translation-editor.html` 文件：无服务器、无需安装、无需 Node.js；
翻译者用 Chrome / Edge 打开即可。页面内置 ZIP 读写库，不调用翻译 API，不上传译文。

## 1. 下载、打开、开始翻译

1. 在仓库根目录点击 [`dolp-kit-translation-editor.html`](../dolp-kit-translation-editor.html)，在 GitHub 文件页选择 **Download raw file / 下载原始文件**，保存为英文文件名的 `.html`。
2. 双击本地 HTML，在浏览器内打开。选择 **中文 / English** 界面均可；修改界面语言不会改动译文。
3. 将 Toolkit 导出的 `localization-kit-001.zip` 等拖入网页，或点击「选择 ZIP 文件」。**不需要解压**，普通 Kit、分片 Kit、repair Kit 均可。
4. 网页按条目显示 `protectedSource` 原文和对应译文输入框。原文中保留的 `⟦0⟧` 等占位符表示受保护的变量、宏、标签或链接结构，不是供译者翻译的文本。
5. 翻译后点击「导出翻译 ZIP」，把生成的 `*-translated.zip` 交给运行 Toolkit 的 Agent；也可以只导出 `segments.jsonl`。

**文件区别：** `manifest.json`、`segments.jsonl`、`segments.csv`、规则文件等都来自 Toolkit；
该网页只编辑翻译字段，导出 ZIP 时同步 JSONL 与 CSV，并保留其他内容。原始 ZIP 不会被覆盖。

## 2. 常用编辑操作

| 操作 | 用法 |
| --- | --- |
| 查找内容 | 搜索原文、译文或 passage 名 |
| 筛选 | 全部、未翻译、已翻译、占位符提醒 |
| 排序 | 原始顺序（默认）或未翻译优先；不会打乱导出中的原始条目顺序 |
| 阅读 | 分页（20 / 40 / 80 条）、字号调整、亮色与深色主题 |
| 单条复制 | 原文与译文框之间的复制按钮把该条**受保护原文**原样放入对应译文框；覆盖不同译文前会确认 |
| 整包复制 | 顶部「将整包原文复制到所有译文框」；会覆盖已有译文，须确认 |
| 输入翻译 | 可自行编辑大文本框；注意格式、语义与 `⟦n⟧` 占位符 |

**注意：复制原文只是方便开始编辑或制作测试数据，并不代表完成翻译。**
即使占位符看起来完整，也可能因无效译文、NO_OP、结构限制等被 Toolkit 拒绝。
不要为了让测试通过而删改占位符或绕过 QA。

## 3. 关键词词典

点击页面侧边的「关键词 / Glossary」打开抽屉，添加例如 `Robin → 罗宾`、`Orphanage → 孤儿院` 的映射。
它只在你点击**某个译文框旁的「替换关键词」按钮**时对当前译文起作用：
不会自动修改原文、其他译文或整包。英文关键词按**大小写敏感的完整单词**匹配；
带占位符的内容应留意替换结果，最后仍由 Toolkit 验证。

- 「导出词典 JSON」会下载 `dolp-translation-keywords.json`，可交给下一位译者。
- 「导入 JSON」会合并词典，遇到同名词条会提示覆盖数量。
- 删除单个词条、清空词典均需要两次确认。
- 浏览器通常把词典保存在 **IndexedDB**，与每个 Kit 分开；**不随翻译 ZIP 导出**。浏览器数据被清理、切换浏览器或部分 `file://` 环境受限时，可能无法恢复。请定期导出 JSON 备份。

`glossary.csv` 是 **Toolkit 原生 Kit 附带的锁定术语表**；
网页侧边栏的 **个人关键词词典** 是便于手动替换的本地工具，两者是两套不同的数据，
不要假设会自动互相同步。

## 4. 多人接力：导入已有译文

先正常打开**基础 Kit ZIP**，再点「导入已有译文 ZIP / JSONL」并选择另一位译者交给你的文件：

- **只填空白（推荐）**：只补你尚未填写的译文；已有且不同的译文会跳过并统计冲突。
- **覆盖不同译文**：以导入者的译文覆盖当前不同内容，实际覆盖前再次确认。
- 支持同一批条目的 ZIP 或独立 `segments.jsonl`。它按 **`unitId`** 匹配，不依赖排列顺序。
- 必须有**相同的完整条目集合**和未变化的原文身份、受保护文本、占位符等字段。ZIP 还核对目标 story SHA-256、inventory fingerprint、语言等。不同 `generatedAt` 或仅信息性版本标签不同并不妨碍同源交接。
- 任何条目不匹配、缺少条目、重复 ID 或 ZIP 内 JSONL/CSV 翻译冲突，整批停止并报告，不会半途混合。

**跨不同分片**请交给 Toolkit 分别 `kit import` 到同一份 `state.jsonl`，不要用网页的接力导入功能强行合并不同分片。

## 5. 草稿、导出与安全

浏览器可在允许时把当前 Kit 的草稿存入 IndexedDB，重新打开同一 Kit 时提示是否恢复。
**不要把浏览器草稿当唯一备份**：定期导出 `*-translated.zip`，并另存一份关键词 JSON。

网页处理文件在本机完成，不访问任何远程 API；内嵌 JSZip 以在浏览器中读取和生成 ZIP。
ZIP 导出使用 **STORE（不压缩）**，兼容 Toolkit 当前只读 STORE ZIP 的导入器。
输出不包含游戏本体、无需修改 APK，也不会自动推送 GitHub。

建议一次处理约 **200–5,000 条**，避免单页负担过重；太多内容就用 Toolkit 的 `--chunk-size` 分片。

## 6. 交还 Toolkit 的正式验收

编辑器的占位符提示是辅助检查，不能证明翻译符合全部保护规则。
让 Agent 使用**对应的同一份目标 story**运行：

```bash
node core/src/run.mjs kit import <filled-kit.zip> --story <target-index.html> --out _work/state.jsonl --require-complete --report _work/import-report.json --repair-output _work/repair-kit.zip
node core/src/run.mjs qa --story <target-index.html> --state _work/state.jsonl --report _work/qa.json
node core/src/run.mjs build --story <target-index.html> --state _work/state.jsonl --output _work/pack.mod.zip --mode strict --report _work/build.json
```

只翻译小部分时，`strict build` 因其余条目未翻译而失败是**预期行为**，可按文档使用
`partial` 用于迭代测试；不得将 partial 当作完整发布包。
发现被拒条目时使用 Agent 导出的 `repair-kit.zip` 修复后重新导入。

若遇到浏览器储存权限、导入兼容或 ZIP 导出问题，请保留**不含私人译文**的最小复现说明，
勿将游戏正文、存档或真实译文提交到公共仓库。
