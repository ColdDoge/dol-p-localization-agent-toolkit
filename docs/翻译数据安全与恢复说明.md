# 翻译数据安全与恢复说明

本说明解释网页翻译编辑器里**哪些数据保存在浏览器、哪些需要你自行导出备份、
游戏翻译包和编辑工程有什么区别**，以及草稿的恢复与清除。

## 1. 三种不同的数据

| 数据 | 内容 | 位置 | 是否进入游戏 |
| --- | --- | --- | --- |
| 游戏使用的翻译文件 | `segments.jsonl` / `segments.csv` | 你导出的 ZIP / JSONL，然后交给 `kit import` | 是 |
| 编辑器工程与状态 | 状态标记、备注、忽略项、可选译文 | 浏览器草稿 + 你导出的 `*.dolpkit.json` | 否 |
| 检查报告 | 安全 / 术语 / 重复原文 / 冲突 / 迁移结果 | 只在界面显示 | 否 |

导出“汉化 ZIP”时，编辑器**只**改写 `segments.jsonl` 和 `segments.csv`，并严格
按规范字段写；你新增的状态标记、备注、忽略项**不会**被写进游戏翻译包。导入到
Toolkit 后，身份字段、哈希、占位符仍由 Toolkit 重新校验。

## 2. 浏览器里保存了什么

* **草稿**：当前 Kit 的译文、状态标记、备注、忽略项、最后保存时间。
  存入浏览器 IndexedDB，库名为 `dolp-kit-translation-editor-v1`。
* **关键词词典**：单独存放，不随 Kit 导出。
* **界面语言偏好**：`localStorage` 里的一个字段。

草稿按**项目标识**隔离。项目标识由目标 story 的 SHA-256、inventory 指纹、
条目数量与首尾条目 ID 共同决定，因此**不会仅凭文件名**把不同项目混在一起。
切换到另一个 Kit 时，上一个项目的忽略项、恢复点与临时分析 / 预览状态都会被
清空；只有恢复草稿时才会载入当前 Kit 自己的数据。

## 3. 自动保存

* 译文改动采用**防抖**保存（约 0.7 秒），避免每次按键都写库。
* 顶部状态栏显示：草稿已保存、正在保存草稿…、草稿保存失败、草稿未修改、
  草稿不可用，并显示最后保存时间。
* 浏览器还会保留少量最近恢复点，降低单次错误写入造成损失的风险。
* 存储空间不足或写入失败时，界面会明确显示“草稿保存失败”，**不会**假装已保存。
* 自动保存**不能**替代你主动导出文件备份。

## 4. 恢复草稿

重新打开同一个 Kit 时，如果本机存在草稿，编辑器会弹出三选一：

1. **恢复草稿**：用草稿里的译文与状态继续工作。
2. **使用刚导入的文件**：以 ZIP 内的译文为准，忽略草稿。
3. **先导出草稿备份**：把草稿导成 `*-draft.dolpkit.json` 保存，再使用导入文件。

如果只想保留状态标记而不想改动译文，可在恢复后再用“导出编辑工程 JSON”
另行备份。

## 5. 清除草稿

“清除本机草稿”需要**两次确认**，且只清除当前项目的草稿，不会影响其他项目，
也不会影响已导出的文件。清除后无法从浏览器恢复，请先导出备份。

## 6. 编辑工程文件（`*.dolpkit.json`）

* 记录格式：`format = "dolp-kit-editor-project"`、`version = 1`，以及
  来源身份、状态标记、备注、忽略项、可选译文与原文。
* 用于跨浏览器 / 跨机器迁移状态，或作为辅助备份。
* 导入时会校验格式。若工程来自**同一个 Kit**，按 `unitId` 合并状态；若来自
  **不同 Kit**，则必须逐个核对工程记录的原文与当前条目一致才合并，
  无法确认的记录会被跳过并报告数量——绝不会仅凭 `unitId` 复用校对状态。
* “忽略的术语提醒”是**按条目**存储的：只有条目身份被确认时才导入；来自
  无法验证的 Kit 的忽略项会被拒绝并报告。有效的忽略项增删同样进入撤销历史、
  触发草稿自动保存并更新“存在未导出修改”。
* 旧文件即使不含新增字段也能导入；缺失的状态按“未标记”处理。

## 7. 冲突与覆盖规则

* 任何“覆盖已有译文”的操作（批量复制原文、交接覆盖、重复原文填充、迁移）
  都会先确认，并且可以撤销。
* 导入与合并**默认只填空白译文**，绝不静默覆盖。
* 重复原文填充遇到“同组多个不同译文”时，不会替你选一种；该组默认跳过，
  需要你在“重复原文”面板中明确选择后才会填充。
* 被替换 / 迁移新内容后，对应条目的校对状态会重置为“未标记”，避免把未经
  校对的新内容误标为“已校对”。

## 9. 未导出状态与草稿

所有真实编辑（单条译文、复制原文、替换关键词、术语修复、批量标记、批量导入、
交接合并、重复原文填充、版本迁移、工程导入）都会：更新“存在未导出的修改”，
触发自动保存草稿，并记录到可撤销历史。导出 ZIP / JSONL 后即视为已导出。

## 8. 安全边界

* 所有处理都在本机浏览器完成，不上传网络。
* 不涉及任何 AI 翻译接口。
* 安全检查、术语检查、重复原文、迁移只会**提示或按需修改**，不会擅自改动译文。
