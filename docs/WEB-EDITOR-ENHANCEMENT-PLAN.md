# 网页翻译工具功能增强：实施计划与风险清单

本文件记录本轮对 `dolp-kit-translation-editor.html` 的功能增强计划、分阶段
顺序与已知风险。它是工作记录，不是用户手册。

## 调查结论（基线）

* 入口：仓库根目录单文件 `dolp-kit-translation-editor.html`（内嵌 JSZip）。
  纯本地、离线、可静态部署，中英文界面通过 `UI.zh` / `UI.en` 切换。
* 数据格式：`kit.zip` 内含 `manifest.json`、`segments.jsonl`、
  `segments.csv`（+可选 `glossary.csv`）。条目身份字段
  `unitId`、`protectedSource`、`placeholders[]`、各哈希字段来自
  `core/src/lib/kit.mjs` 的 `segmentFromUnit`；原文结构（宏 / 变量 / HTML /
  链接）在 `protectedSource` 中已被替换为 `⟦n⟧` 占位符。
* 已有能力：导入 / 导出 Kit（ZIP、JSONL）、复制单条 / 全部原文、关键词词典
  （IndexedDB）、关键词替换、交接导入（只填空白 / 覆盖）、搜索、状态筛选
  （全部 / 未翻译 / 已翻译 / 占位符提醒）、排序、分页、字号、深色模式、
  草稿自动保存与恢复（单一恢复点）。
* 缺失：安全结构检查、状态标记、撤销 / 重做、多模式合并预览、术语一致性
  检查、重复原文识别、版本迁移、可导出的编辑工程文件、多恢复点。

## 阶段

* 阶段 A（数据安全）：编辑工程 sidecar、自动保存增强（状态提示、多恢复点、
  清除确认、写失败告警）、撤销 / 重做。
* 阶段 B（检索与检查）：搜索 + 高级筛选统一管线、进度统计与状态标记、
  安全检查与定位。
* 阶段 C（一致性与协作）：术语一致性检查、重复原文识别、安全合并与冲突预览。
* 阶段 D（版本迁移）：新旧翻译差异分析、预览、报告、可撤销迁移。

## 架构决定

* 游戏使用的 Kit 导出格式保持不变：`segments.jsonl` 只写规范字段（不再
  `JSON.stringify` 整个对象），`segments.csv` 保持原列；编辑状态、备注、
  忽略项、导出序号只写入浏览器草稿与独立的编辑工程文件
  `*.dolpkit.json`，绝不进入 `kit.zip`。
* 所有纯逻辑放在 HTML 内 `DOLP-EDITOR-ENGINE` 标记区，无 DOM 依赖；
  Node 测试直接从 HTML 抽取该区并执行，保证测试的是真实源码。

## 风险清单

* 单文件 HTML 无构建步骤：只能用标记区 + 抽取测试，不能拆分模块。
* 状态元数据若写入 `segments.jsonl` 会污染游戏翻译包 → 用独立 sidecar。
* 撤销不能深拷贝整包 → 按受影响 unitId 稀疏记录 before/after。
* 安全检查必须有真实依据，避免把所有 `<`、`{`、`%` 都当变量 → 只比对
  `⟦n⟧` 占位符与显式结构（`<<>>`、`[[ ]]`、HTML 标签、`$var`），
  其余只给 info。
* 迁移 / 合并误匹配风险 → 默认只填空白，逐条 / 预览，全部可撤销，报告
  分类，绝不静默覆盖。
