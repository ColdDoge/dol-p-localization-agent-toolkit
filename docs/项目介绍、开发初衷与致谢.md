> **说明：** 这是一个独立的第三方本地化工具 / 自动化实验项目，不属于现有 DoL / DoLP 汉化组。本仓库**不提供现成汉化包、游戏 APK 或游戏中文译文正文**。如果用本项目生成的本地化包遇到问题，请向本项目反馈，不要向原汉化组报错。

## 这个项目主要提供什么

它是一套本地、离线优先的汉化工程工具链，面向 DoL / DoLP，以及其他符合相关 SugarCube / ModI18N 工作流的目标。主要功能包括：

- 从目标游戏文件中提取、分类可翻译文本；
- 检查已有汉化的覆盖率，找出未翻译、发生变化或需要处理的内容；
- 导出待翻译文本包，在人工或外部翻译流程完成后导入译文；
- 尽量保护 placeholder、macro、variable、HTML 等游戏结构，进行结构检查和 QA；
- 根据已验证的数据构建汉化 Mod，报告构建障碍；
- 游戏更新后检查旧译文能否安全迁移，区分可复用与需要重新处理的内容；
- 按需使用 Android 真机，对实际显示效果进行自动化运行时验证。

**工具本身不提供翻译功能。** 译文可以由人工完成，也可以由使用者自行选择外部翻译工具或 Coding Agent。工具处理的是文本提取、结构保护、回填、构建、版本迁移和调试等工程环节。

## 附带的网页翻译编辑器

**[下载单文件网页编辑器](../dolp-kit-translation-editor.html)** · [中文使用指南](翻译编辑器使用指南.md) · [English guide](KIT-EDITOR-GUIDE.en.md)

考虑到手工修改 CSV / JSONL 对不熟悉文件格式的用户不够友好，项目还提供了一个单文件网页编辑器：`dolp-kit-translation-editor.html`。

在 GitHub 文件页面选择 **Download raw file / 下载原始文件**，保存 HTML 后，用 Chrome 或 Edge 在本地打开即可。无需安装软件或搭建服务器，也不需要 Node.js。网页在浏览器本地读取、处理和导出文件，不会将 Kit 或译文上传到远程翻译服务。

目前的主要功能有：

- 直接导入 Toolkit 导出的 Kit ZIP，逐条阅读受保护的原文并填写译文；
- 中英文界面、搜索、筛选、分页、原始顺序 / 未翻译优先排序、字号和亮暗主题；
- 单条或整包将原文原样复制进对应译文框，方便准备试译数据或保留原有结构；
- 建立个人关键词词典，按需在单条译文中执行关键词替换，并独立导入 / 导出词典 JSON；
- 导入其他译者交回的**同一批条目**的 ZIP 或 `segments.jsonl`，核对身份后接力合并；默认只填空白，覆盖已有不同译文需要确认；
- 导出更新后的 ZIP 或 `segments.jsonl`；ZIP 中的相关译文字段同步更新，不覆盖原始压缩包；
- 在浏览器允许时本地保存翻译草稿和关键词词典。

**使用时请注意：** 浏览器草稿不是可靠的唯一备份，请定期导出翻译 ZIP 和词典 JSON。复制原文并不意味着翻译完成；网页中的占位符提示也不能替代 Toolkit 的完整结构 QA。正式导入、构建和发布前，仍需运行相应的导入、检查与构建流程。编辑器没有内置 AI 翻译功能。

## 为什么做这个

这个项目开发过程中大量使用了 AI 辅助和自动化工具，包括 ChatGPT、Codex 等 Agent，主要用于源码调查、工具开发、文本处理、静态 QA 和自动调试。但 **AI 翻译本身并不是这个项目最主要的目标**。

单论译文质量，我认为目前 AI 翻译与成熟的人工汉化相比仍有明显差距：容易显得生硬、带有固定句式和“AI 味”，对角色语气、作品文风以及一些比较强烈的表达，也常常处理得不够理想。

因此，我更想做的是一套尽可能自动化、同时对普通用户相对友好的本地化工具链。例如：

1. 给 Agent 一个目标版本的游戏文件、APK 或提取出的 `index.html`，让它尽量自动完成目标识别、文本提取、分类、结构保护和待译文本包的准备；
2. 人工或外部工具完成翻译后，重新导入译文，由工具检查结构、覆盖率、冲突并构建本地化包；
3. 游戏更新时，尽量自动辨别哪些旧译文还能安全复用，哪些需要重新处理，减轻重复劳动；
4. 成品生成后，可以选择进一步使用真机自动化调试，记录无法通过的部分，供人检查和修复。

这些是工具的目标和工作流方向，并不意味着所有游戏版本、所有文本或所有运行时问题都能完全自动处理。项目目前仍处于实验和完善阶段。

我开始考虑这件事，还有一部分原因是曾看到一些非中文 DoL 本地化版本长期没能跟上游戏更新：即使有人愿意翻译和维护，如果还必须先学会 ModI18N、源码结构、变量和宏、补丁构建、版本迁移以及 Android 调试，技术门槛也会非常高。

对于原本就想维护某种语言的个人译者、小语种本地化维护者，或单纯想练习翻译的人，我希望这些繁琐的工程环节能少占用一些精力。工具也不限定只能做简体中文；在适用的前提下，同样可以服务于其他语言的本地化。

**最终希望做到的是：让想翻译的人更容易把精力放在翻译本身，而不是先学习一大堆本地化工程和调试流程。**

如果不喜欢 AI 译文，也完全可以只使用文本提取、分类、导入、QA、构建、版本迁移和调试功能。已有成熟人工汉化已经符合需要的话，也没有必要为使用工具而更换它。

## 怎么开始使用

仓库首页提供了按用途整理的[中文 Agent 提示词](PROMPTS.zh-CN.md)和[英文 Agent 提示词](PROMPTS.en.md)：从零开始汉化、检查已有版本、迁移到新游戏版本、构建与 QA、选择性真机验证等。

对于使用 Coding Agent 的用户，可以从一个**空工作目录**开始，把对应的完整提示词交给能够读写文件、运行命令的 Agent。它会按照仓库公开文档获取工具、读取工作流，并在需要时索要目标文件。也可以不用 Agent，直接参照 [中文 README](../README.zh-CN.md) 和 CLI 文档手动操作。

根据目标任务，可能需要：

- **Node.js 22 或更新版本**：用于运行离线 Toolkit；
- **目标游戏文件**：实际分析对象通常是编译后的 `assets/www/index.html`；如果只有 APK，可以先从中提取相应文件；
- **与目标版本兼容的 ModLoader**：用于实际加载生成的 Mod 和开展相关运行时验证；
- **ADB + 开启 USB 调试的 Android 设备**：只在需要真机调试时使用；
- **能够读写本地文件和运行命令的 Agent 环境**：只在希望通过 Agent 执行工作流时需要。

**离线提取、检查、导入、迁移和构建无需连接手机，也不需要 ADB。** 本仓库不提供游戏 APK 下载，也不负责一般性的 APK 安装问题；游戏与对应 ModLoader 请自行准备。

完整的参数、工作流与限制，请查看 [中文 README](../README.zh-CN.md)、[工作流说明](AGENT-WORKFLOW.md)及[工具总览](TOOLKIT-OVERVIEW.md)。

## 自动 QA 的边界

自动检查主要针对文本覆盖率、placeholder / macro / variable / HTML 等结构、补丁冲突、版本迁移状态和部分运行时问题。

**通过这些检查，并不能保证译文一定准确、自然或符合角色文风。** 完整本地化仍然需要人工阅读、润色和必要的游戏内检查。一些由 widget / JavaScript 动态生成的文本，也可能需要额外处理。

## 开发与测试时使用的工具

开发和测试中使用过 **ChatGPT Chat / Codex + DeepSeek V4.1 Flash** 等工作环境。它们只代表项目开发阶段实际使用过的工具组合，并非 Toolkit 的绑定依赖；用户可以根据情况采用其他 Agent，或完全手动操作。
