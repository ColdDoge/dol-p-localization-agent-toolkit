# 新工作区从零验收指南

给**没有任何历史上下文**的 Agent：在一个全新目录里，从零把本工具链跑通、并完成一次可复现的验收。

本文是**流程索引**，不重复技术细节。每一步都指向已有文档，遇到具体规则请读那一份。

> 前提：`_work/` 与 `_local/` **不会**随 `git clone` 出现，它们是被 gitignore 的本地目录，需要自己建。
> 游戏 story、ModLoader、译文、设备信息都**由用户提供**，仓库里只有合成示例。

---

## 0. 必须先分清的三类东西

| 类别 | 谁提供 | 放在哪 | 会进 Git 吗 |
| --- | --- | --- | --- |
| 目标游戏文件（`assets/www/index.html`、APK、ModLoader 包、图片包） | **用户** | `_work/`、`_local/` 或外部目录 | 不会 |
| 译文 / 术语表 / localization state / kit / pack | 用户与工具 | `_work/`、`_local/` | 不会 |
| 工具代码、文档、schema、示例 | 仓库 | 仓库内 | 会 |

**永远不要**把上面第一、二类提交进仓库；也不要拿仓库里的 `examples/story/index.html` 当真实目标
（它只是合成数据）。

---

## 1. 克隆与依赖

```powershell
git clone https://github.com/ColdDoge/dol-p-localization-agent-toolkit.git
cd dol-p-localization-agent-toolkit
node --version      # 需要 >= 22
```

没有其他运行时依赖（无 npm 安装步骤）。先读 [`README.md`](../README.md)、
[`AGENTS.md`](../AGENTS.md)、[`docs/TOOLKIT-OVERVIEW.md`](TOOLKIT-OVERVIEW.md)、
[`docs/AGENT-WORKFLOW.md`](AGENT-WORKFLOW.md)。

自检（离线，任何时候都能跑）：

```powershell
node core/src/selftest.mjs                      # 期望 60 passed
npm test --prefix core                          # 期望 98 passed
node --test runtime/android/test/*.test.mjs     # 期望 44 passed
```

## 2. 建立本地工作目录

```powershell
New-Item -ItemType Directory -Path _work, _local -Force
```

把用户提供的 **目标 story**（编译后的 `assets/www/index.html`）放到 `_work/index.html`。
如果用户只给了 APK，用普通压缩工具只取出这一个文件即可（不是本工具的 CLI 功能）。

## 3. 离线主流程

严格按 [`docs/AGENT-WORKFLOW.md`](AGENT-WORKFLOW.md) 的"标准循环"执行，命令语法见
[`docs/OPTIONS.md`](OPTIONS.md)，各命令包含的检查见 [`docs/PROTECTION-RULES.md`](PROTECTION-RULES.md)。

```powershell
$S = "$PWD\_work\index.html"

# 3.1 盘点：知道自己面对多少单元
node core/src/run.mjs inventory --story $S --source-version "<用户给的版本>" --out _work/inventory.json

# 3.2 导出待翻译文本（目标很大时用分片）
node core/src/run.mjs kit export --story $S --scope all `
  --chunk-size 5000 --output-dir _work/kits --target-language zh-CN

# 3.3 交给译者：只填 segments.jsonl 的 translation 字段（详见 docs/LOCALIZATION-KIT.md）

# 3.4 导入 + QA + 迭代包
node core/src/run.mjs kit import _work/kits-filled/localization-kit-001-filled.zip `
  --story $S --out _work/state.jsonl --require-complete `
  --report _work/import-report.json --repair-output _work/repair-kit.zip
node core/src/run.mjs qa    --story $S --state _work/state.jsonl --report _work/qa.json

# 3.5 构建
node core/src/run.mjs build --story $S --state _work/state.jsonl `
  --output _work/pack.mod.zip --mode strict --report _work/build.json
```

**失败时怎么办**：`kit import` 永远扫描整个包，不会因为第一条失败就停。
被拒 / 未填 / JSONL-CSV 冲突的条目会集中进 `repair-kit.zip`（含 `issues.jsonl`）；
只修那几条再导回**同一个** `state.jsonl`，不要重导原始整包。

* `strict` 失败 → 报告 blocking coverage（`untranslated` / `rejected-structure` / `superseded` / `unresolved`）
  和逐条原因，**不要**把 `partial` 包当发布结果；
* `partial` 只用于迭代，报告里会写 `partial: true`；
* 任何情况下都**不要**削弱 placeholder / reversible / V3 / duplicate / overlap / replay 检查。

## 4. Android 真机（可选）

只有在用户**明确授权**后才做。完整前置条件、安全边界与命令见
[`docs/RUNTIME-VALIDATION.md`](RUNTIME-VALIDATION.md)；分级语义见
[`docs/RUNTIME-QA-MODES.md`](RUNTIME-QA-MODES.md)；场景选择见
[`docs/RUNTIME-SMOKE-V1.md`](RUNTIME-SMOKE-V1.md)。

```powershell
# 4.1 本地配置（gitignore；不要把真实设备信息写进仓库）
#     _local/android-config.local.json
#     { "serial": "...", "package": "...", "cdpPort": 50806, "androidCli": "android",
#       "devToolsPath": "<可选：DoL-Dev-Tools-Paisley-Park 安装目录>" }

node runtime/android/doctor.mjs                     # 只读体检，必须先通过
```

### 4.2 先核对设备 build 身份（重要）

**不要**假定设备上的版本和用户给的 story 一致。做法与判定口径见
[`docs/Paisley-Park-3.0.2-接入与验收.md`](Paisley-Park-3.0.2-接入与验收.md) §4，
以及本工具链的对比思路：**两边用同一条提取与规范化规则**比较 passage，
不要直接比较不同打包方式的文件哈希。

若设备 build 与 story 不一致：

* 只在与设备一致的那部分 passage 上做断言；
* 明确记录差异数量与未验证范围；
* **不要**宣称目标版本全量通过，也不要去改版本标签或身份字段。

### 4.3 smoke / regression

```powershell
# 从 state 生成场景表（期望值必须由真实译文推导，不要手写）
node runtime/localization_smoke_build.mjs --story $S --state _work/state.jsonl `
  --scenarios _work/scenarios.json --level exhaustive --out-dir _work/localization-smoke

node runtime/android/test-localization-runtime.mjs --level smoke
node runtime/android/test-localization-runtime.mjs --level regression
```

`--level` 会按场景文件的 `levels` 登记筛选（expectations 里带完整登记表）；
判读要点：tier A 要求目标语言片段出现且指定源文片段消失，tier C 只要求界面仍可用。

### 4.4 结束后必须核对

* 临时 Mod 已移除（ModLoader `listModIndexDB` 回到测试前的值）；
* 页面无错误（`bodyErrors = 0`）；
* 未清除 App 数据、未覆盖存档、未卸载任何应用；
* 有备份时，记录备份文件位置与大小。

## 5. 最终报告要写什么

1. 目标 story 的 sha256、单元数、命中过的命令；
2. coverage 六个状态的数量与最终产物路径；
3. 设备 build 身份比对结果（相同/不同的 passage 数量）与**未验证范围**；
4. 每条 blocker 的具体原因（不要只给总数）；
5. 如果用了 Paisley Park：它负责的采集/证据在哪，以及未做的部分（Action/Journey 需要单独授权）。

## 6. 可选：Paisley Park 现场调查

需要截图、DOM/CSS、Console/Network 摘要或更复杂的场景导航时，用外部工具
DoL Dev Tools: Paisley Park（安装、Skill、实测限制见
[`docs/Paisley-Park-3.0.2-接入与验收.md`](Paisley-Park-3.0.2-接入与验收.md)）。

要点：**离线汉化流程不依赖它**；在 DoLP 上必须显式传 `--target-id`；
涉及游戏操作（Action/Journey/Gameplay）前必须拿到用户授权与恢复条件。

