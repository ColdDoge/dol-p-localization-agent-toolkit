# 新工作区从零验收指南

给**没有任何历史上下文**的 Agent：在一个全新目录里，从零把本工具链跑通、并完成一次可复现的验收。

本文是**流程索引**，不重复技术细节。每一步都指向已有文档，遇到具体规则请读那一份。

> 前提：`_work/` 与 `_local/` **不会**随 `git clone` 出现，它们是被 gitignore 的本地目录，需要自己建。
> 游戏 story、ModLoader、译文、设备信息都**由用户提供**，仓库里只有合成示例。

---

## 0. 必须先分清的三类东西

| 类别 | 谁提供 | 放在哪 | 会进 Git 吗 |
| --- | --- | --- | --- |
| 目标游戏文件（`assets/www/index.html`、APK、ModLoader 包、图片包） | **用户** | `_work/`、`_local/` 或外部目录 | 不会 |
| 译文 / 术语表 / localization state / kit / pack | 用户与工具 | `_work/`、`_local/` | 不会 |
| 工具代码、文档、schema、示例 | 仓库 | 仓库内 | 会 |

**永远不要**把上面第一、二类提交进仓库；也不要拿仓库里的 `examples/story/index.html` 当真实目标
（它只是合成数据）。

---

## 1. 克隆与依赖

```powershell
git clone https://github.com/ColdDoge/dol-p-localization-agent-toolkit.git
cd dol-p-localization-agent-toolkit
node --version      # 需要 >= 22
```

没有其他运行时依赖（无 npm 安装步骤）。先读 [`README.md`](../README.md)、
[`AGENTS.md`](../AGENTS.md)、[`docs/TOOLKIT-OVERVIEW.md`](TOOLKIT-OVERVIEW.md)、
[`docs/AGENT-WORKFLOW.md`](AGENT-WORKFLOW.md)。

自检（离线，任何时候都能跑）：

```powershell
node core/src/selftest.mjs                      # 期望 60 passed
npm test --prefix core                          # 期望 98 passed
node --test runtime/android/test/*.test.mjs     # 期望 44 passed
```

## 2. 建立本地工作目录

```powershell
New-Item -ItemType Directory -Path _work, _local -Force
```

把用户提供的 **目标 story**（编译后的 `assets/www/index.html`）放到 `_work/index.html`。
如果用户只给了 APK，用普通压缩工具只取出这一个文件即可（不是本工具的 CLI 功能）。

## 3. 离线主流程

严格按 [`docs/AGENT-WORKFLOW.md`](AGENT-WORKFLOW.md) 的"标准循环"执行，命令语法见
[`docs/OPTIONS.md`](OPTIONS.md)，各命令包含的检查见 [`docs/PROTECTION-RULES.md`](PROTECTION-RULES.md)。

```powershell
$S = "$PWD\_work\index.html"

# 3.1 盘点：知道自己面对多少单元
node core/src/run.mjs inventory --story $S --source-version "<用户给的版本>" --out _work/inventory.json

# 3.2 导出待翻译文本（目标很大时用分片）
node core/src/run.mjs kit export --story $S --scope all `
  --chunk-size 5000 --output-dir _work/kits --target-language zh-CN

# 3.3 交给译者：只填 segments.jsonl 的 translation 字段（详见 docs/LOCALIZATION-KIT.md）

# 3.4 导入 + QA + 迭代包
node core/src/run.mjs kit import _work/kits-filled/localization-kit-001-filled.zip `
  --story $S --out _work/state.jsonl --require-complete `
  --report _work/import-report.json --repair-output _work/repair-kit.zip
node core/src/run.mjs qa    --story $S --state _work/state.jsonl --report _work/qa.json

# 3.5 构建
node core/src/run.mjs build --story $S --state _work/state.jsonl `
  --output _work/pack.mod.zip --mode strict --report _work/build.json
```

人类译者如不想直接编辑 CSV/JSONL，可选择仓库根目录的
[`dolp-kit-translation-editor.html`](../dolp-kit-translation-editor.html)：
下载原始 HTML 后离线打开 ZIP，填写并导出新的完整 Kit。详细操作见
[中文指南](翻译编辑器使用指南.md) / [English guide](KIT-EDITOR-GUIDE.en.md)。
此网页是**可选编辑界面**，不会生成译文，也不取代 `kit import` 的保护检查。
多人交接时仅合并相同原文身份和条目集合的 Kit，不会跨分片猜测匹配。

**失败时怎么办**：`kit import` 永远扫描整个包，不会因为第一条失败就停。
被拒 / 未填 / JSONL-CSV 冲突的条目会集中进 `repair-kit.zip`（含 `issues.jsonl`）；
只修那几条再导回**同一个** `state.jsonl`，不要重导原始整包。

* `strict` 失败 → 报告 blocking coverage（`untranslated` / `rejected-structure` / `superseded` / `unresolved`）
  和逐条原因，**不要**把 `partial` 包当发布结果；
* `partial` 只用于迭代，报告里会写 `partial: true`；
* 任何情况下都**不要**削弱 placeholder / reversible / V3 / duplicate / overlap / replay 检查。

## 4. Android 真机（可选）

只有在用户**明确授权**后才做。完整前置条件、安全边界与命令见
[`docs/RUNTIME-VALIDATION.md`](RUNTIME-VALIDATION.md)；分级语义见
[`docs/RUNTIME-QA-MODES.md`](RUNTIME-QA-MODES.md)；场景选择见
[`docs/RUNTIME-SMOKE-V1.md`](RUNTIME-SMOKE-V1.md)。

```powershell
# 4.1 本地配置（gitignore；不要把真实设备信息写进仓库）
#     _local/android-config.local.json
#     { "serial": "...", "package": "...", "cdpPort": 50806, "androidCli": "android",
#       "devToolsPath": "<可选：DoL-Dev-Tools-Paisley-Park 安装目录>" }

node runtime/android/doctor.mjs                     # 只读体检，必须先通过
```

### 4.2 先核对设备 build 身份（重要）

**不要**假定设备上的版本和用户给的 story 一致。做法与判定口径见
[`docs/Paisley-Park-3.0.2-接入与验收.md`](Paisley-Park-3.0.2-接入与验收.md) §4，
以及本工具链的对比思路：**两边用同一条提取与规范化规则**比较 passage，
不要直接比较不同打包方式的文件哈希。

若设备 build 与 story 不一致：

* 只在与设备一致的那部分 passage 上做断言；
* 明确记录差异数量与未验证范围；
* **不要**宣称目标版本全量通过，也不要去改版本标签或身份字段。

### 4.3 smoke / regression

```powershell
# 从 state 生成场景表（期望值必须由真实译文推导，不要手写）
node runtime/localization_smoke_build.mjs --story $S --state _work/state.jsonl `
  --scenarios _work/scenarios.json --level exhaustive --out-dir _work/localization-smoke

node runtime/android/test-localization-runtime.mjs --level smoke
node runtime/android/test-localization-runtime.mjs --level regression
```

`--level` 会按场景文件的 `levels` 登记筛选（expectations 里带完整登记表）；
判读要点：tier A 要求目标语言片段出现且指定源文片段消失，tier C 只要求界面仍可用。

### 4.4 结束后必须核对

* 临时 Mod 已移除（ModLoader `listModIndexDB` 回到测试前的值）；
* 页面无错误（`bodyErrors = 0`）；
* 未清除 App 数据、未覆盖存档、未卸载任何应用；
* 有备份时，记录备份文件位置与大小。

### 4.5 本轮实机验收记录（localization smoke/regression）

> 一次真实运行的结论记录。命令与判读口径见 §4.1–4.4 及
> [`RUNTIME-QA-MODES.md`](RUNTIME-QA-MODES.md) / [`RUNTIME-SMOKE-V1.md`](RUNTIME-SMOKE-V1.md)。
> 设备 serial、目标包名、story 与 pack 的 sha256 只写在 gitignore 的
> `_local/android-config.local.json` 与 `_work/` 报告里，**不进入仓库**。

* **结果**：`--level smoke` 与 `--level regression` 均 `PASSED`，`cleanup RESTORED`
  （临时 mod 已移除、ModLoader `listModIndexDB` 已恢复、`bodyErrors = 0`）。
* **可靠性修正（harness）**：导入汉化包之前先在**未加载 pack** 的状态下跑一遍同样的场景
  （control pass）取基线，把页面可见错误分为 *pre-existing*（原游戏/测试环境已有）与
  *introduced*（打包后才出现）；**只有 introduced 判失败**。本轮 6 个 tier A 场景里
  `[ERROR: undefined pronoun …]`（游戏代词 / `<<person>>` widget 在裸会话下无法解析）
  全部判为 pre-existing，未被误报成汉化回归。`--no-baseline` 可关闭对照。
* **未覆盖（BLOCKED）**：`Hopeless Cycle Prayer Report` 需要 Hopeless Cycle 剧情状态，
  裸会话下游戏自身的 widget 会报错；已标记为 `NOT COVERED`，**不计入通过**
  （原始失败记录保留在本地 `_work/`，不作为通过项）。
* **版本身份边界**：目标 story（翻译基线）为 DoLP `0.5.12.8 / v0.775`，
  实机 build 为 `0.5.12.6 / v0.772`，两者 sha256 不同。16610 个 passage 中
  16424 内容一致、64 不同（集中在 Widgets/UI）。**本轮只证明“内容一致的试译 passage
  正常”，不代表 v0.772 全版本兼容。**
* **已知限制**：状态栏/UI 文本仍为英文（如 `You feel drowsy.`、`Stress`、`Next`、
  版本横幅，以及 `<<person>>` 输出的英文名词），不在试译 Kit 覆盖范围；本轮**未安装
  Paisley Park**，故无截图/DOM/备份证据（`--no-backup`）。

## 5. 最终报告要写什么

1. 目标 story 的 sha256、单元数、命中过的命令；
2. coverage 六个状态的数量与最终产物路径；
3. 设备 build 身份比对结果（相同/不同的 passage 数量）与**未验证范围**；
4. 每条 blocker 的具体原因（不要只给总数）；
5. 如果用了 Paisley Park：它负责的采集/证据在哪，以及未做的部分（Action/Journey 需要单独授权）。

## 6. Android 工具初始化（**只在需要时**）

需要截图、DOM/CSS、Console/Network 摘要、备份或更复杂的场景导航时，才引入外部工具
DoL Dev Tools: Paisley Park。**离线汉化（inventory / kit / import / qa / build）不依赖它，
也绝不在离线阶段强制安装 Android 工具。** 判据很简单：本轮没有"要看真机现场"的需求，就不要装。

需要时按下面的顺序做，任何一步失败都要**报告原因并停下**：

### 6.1 查询与下载

1. 查询 GitHub 上的**最新稳定 Release**（不要用 draft / pre-release，不要用被撤版的 tag）：

   ```powershell
   $rel = Invoke-RestMethod -Uri 'https://api.github.com/repos/102326/DoL-Dev-Tools-Paisley-Park/releases/latest' -Headers @{ 'User-Agent'='codex' }
   $rel.tag_name; $rel.assets | Select-Object name,size,digest,browser_download_url
   ```

2. 下载 release 里的 zip **和** 官方 `SHA256SUMS.txt`。

### 6.2 校验（**不允许跳过**）

三方核对，全部一致才继续：

| 来源 | 用途 |
| --- | --- |
| `SHA256SUMS.txt`（Release 资产） | 官方给出的期望值 |
| GitHub API 的 `assets[].digest` | 独立来源的期望值 |
| 本地 `Get-FileHash -Algorithm SHA256` | 实际下载物的哈希 |

```powershell
Get-FileHash .\DoL-Dev-Tools-Paisley-Park-<VER>.zip -Algorithm SHA256
```

**校验失败、或缺少 SHA256 信息时，不要安装、不要"先试再说"**：报告原因后停止。

### 6.3 安装到 `_local/devtools/`

```powershell
New-Item -ItemType Directory -Path _local/devtools -Force
# 注意：Release 压缩包内没有顶层目录，必须解压到专用子目录，否则会散落到父目录
New-Item -ItemType Directory -Path _local/devtools/DoL-Dev-Tools-Paisley-Park-<VER> -Force
Expand-Archive -LiteralPath .\DoL-Dev-Tools-Paisley-Park-<VER>.zip -DestinationPath _local/devtools/DoL-Dev-Tools-Paisley-Park-<VER>
```

* **不覆盖用户文件**：目标目录里已有内容就换目录或先与用户确认，绝不就地覆盖；
* **不覆盖旧版本工具**：装了新版也把旧目录留着，便于回退；
* `_local/` 已被 gitignore；工具与它的 `node_modules`、`artifacts/` 都不要进仓库。

### 6.4 依赖与自检

```powershell
cd _local/devtools/DoL-Dev-Tools-Paisley-Park-<VER>
npm ci --ignore-scripts --no-audit --no-fund     # 官方 README 指定的锁定安装
.\Paisley-Park.cmd --version
.\Paisley-Park.cmd doctor --out artifacts/doctor.json
```

只装**确有必要的组件**：Node ≥ 22、ADB、WebView 调试是硬需求；Android CLI / Python / scrcpy
按用到的命令再装。`doctor` 若报必需项不可用，先修环境再继续。

### 6.5 配置 `devToolsPath`

在 `_local/android-config.local.json`（gitignore，**不要提交**）里指向安装目录：

```jsonc
{ "devToolsPath": "…\\_local\\devtools\\DoL-Dev-Tools-Paisley-Park-<VER>" }
```

本工具链的 `runtime/android/backup.mjs` / `inspect.mjs` 会直接复用该目录下的脚本；
`node runtime/android/doctor.mjs` 应显示 `DoL-Dev-Tools: found`。

### 6.6 使用 Codex 时安装/更新 Skill

```powershell
node scripts/dol-dev.cjs install-skill --out "$env:USERPROFILE/.codex/skills/dol-dev-tools-paisley-park"
node "$env:USERPROFILE/.codex/skills/dol-dev-tools-paisley-park/scripts/resolve.cjs"
```

* **不得覆盖已有 Skill**：目标必须是**尚不存在**的目录；已有安装会拒绝覆盖并返回非零
  （实测：目标已存在 → 报错退出，原 `SKILL.md` 哈希不变）。要更新就**先备份旧目录**，再装到新的空目标；
* 安装后必须跑 `resolve.cjs` 核对：`version` 与安装版本一致、`cli` / `docs` 指向新的工具目录；
* 解析器自述只证明"位置正确"，**不证明代码可信**——来源仍以 §6.1/§6.2 的 Release 与校验为准；
* 新装的 Skill 通常**从下一个对话回合**才被发现；本轮只能验证显式调用与解析器。

### 6.7 搬迁 / 重装时的核对（旧 Skill 可能指向已删除的目录）

上游会把**机器专属的绝对链接**写进 `SKILL.md`（指向工具自己的 `docs/`）。工具目录一旦被移动、
重命名或删除，这些链接就失效。搬迁或重建工作区后至少做三件事：

1. 用解析器 + 一段就地检查，确认记录的根目录与 `SKILL.md` 里的绝对链接都还在
   （不依赖任何额外脚本，复制即可用）：

   ```powershell
   node "$env:USERPROFILE/.codex/skills/dol-dev-tools-paisley-park/scripts/resolve.cjs"

   $skill = "$env:USERPROFILE/.codex/skills/dol-dev-tools-paisley-park"
   $root  = (Get-Content "$skill/tool-location.json" -Raw | ConvertFrom-Json).toolRoot
   "toolRoot: $root  exists=$(Test-Path -LiteralPath $root)"
   $paths = [regex]::Matches((Get-Content "$skill/SKILL.md" -Raw), '[A-Za-z]:[\\/][^<>\r\n`"|]+') |
     ForEach-Object { ($_.Value -replace '[.,;:)\]]+$','').Split('#')[0] } | Sort-Object -Unique
   $missing = $paths | Where-Object { -not (Test-Path -LiteralPath $_) }
   if ($missing) { "MISSING:"; $missing } else { "all $($paths.Count) referenced paths exist" }
   ```

   期望：`toolRoot` 存在、最后一行是 `all N referenced paths exist`（没有 `MISSING:`）。
2. 若链接失效：**保留旧 Skill 目录作为备份**，把新包解压到新的稳定目录，再按 §6.6 安装到**新的空目标**
   （不要只改旧安装里的文字）；
3. 需要临时指向别处（例如回退旧版本）时，用环境变量覆盖，它优先于安装记录，且不改动任何文件：

   ```powershell
   $env:DOL_DEV_TOOLS_HOME = '<另一个工具目录>'
   node "$env:USERPROFILE/.codex/skills/dol-dev-tools-paisley-park/scripts/resolve.cjs"
   ```

   实测：把 `DOL_DEV_TOOLS_HOME` 指向旧版目录后，解析器如实报出旧版版本号。

### 6.8 失败与降级

* 下载失败 / 校验不一致 / `doctor` 必需项缺失 / Skill 安装被拒 → **报告原因并停下**；
* **不跳过校验**，**不擅自降级**到无校验安装、也不要用旧版本顶替新版本而不说明；
* 真机操作（Action / Journey / Gameplay、安装辅助 APK、写游戏状态）在动手前必须先拿到用户授权与恢复条件；
* 3.0.2 在 DoLP 上的两条实测限制（必须显式 `--target-id`、`gameVersion` 读不到）见
  [`Paisley-Park-3.0.2-接入与验收.md`](Paisley-Park-3.0.2-接入与验收.md)。
