本报告记录本轮对 `dolp-kit-translation-editor.html` 的功能增强所新增的自动化
测试、实际执行结果、数据兼容性结论与已知限制。所有命令均为离线执行。

## 二、新增测试文件

编辑器是没有构建步骤的单文件 HTML，因此测试直接从 HTML 中**抽取真实源码**后在
Node 中执行，不做逻辑复制。

### 1. `core/test/translation-editor.test.mjs`（18 项）

抽取 HTML 内 `DOLP-EDITOR-ENGINE` 标记区的纯函数，验证：

* 占位符提取与完整性：合法、乱序、缺失、多出、错位。
* 安全检查：合法译文无错误；缺失占位符判为错误；手打宏被判为警告；
  普通标点（`%`、`{}`、非标签尖括号）不产生误报；与原文相同只判为提示。
* 术语检查：英文整词、区分大小写、可忽略。
* 重复原文分组与“仅填空白”计划。
* 视图管线：搜索 → 筛选 → 排序，且不修改原始数据；状态 / 问题 / 重复 / 冲突筛选。
* 统计：已翻译的判定规则、状态分桶、问题条目数、百分比。
* 交接计划：fill / keep / preview / overwrite 语义；overwrite 才覆盖冲突。
* 迁移计划：A/B/C/D 分类；同 ID 改原文**不**自动迁移。
* 编辑工程：格式 / 版本校验与脏数据清洗。

### 2. `core/test/translation-editor-workflow.test.mjs`（11 项）

在 Node `vm` 中用最小 DOM / IndexedDB 桩**启动真实的应用脚本**，驱动真实处理
逻辑，覆盖用户工作流：

* 载入 Kit → 编辑 → 导出 JSONL，且 `segments.jsonl` **只**含规范字段，
  状态 / 备注不会泄漏进游戏翻译包。
* 批量编辑作为**一组**撤销 / 重做；撤销后再编辑会清除重做分支。
* 交接合并：默认只填空白、保留冲突；显式覆盖才替换；一次可撤销。
* 覆盖后对应条目状态重置为“未标记”（不把未校对内容误标为已校对）。
* 草稿自动保存（写出后才显示“已保存”）、按项目隔离、重开时“恢复草稿”生效。
* 迁移只向空白条目填充稳定匹配项，改原文的条目不迁移。
* 编辑工程导出 / 导入往返保留状态与备注。
* 统计为整包范围，不受当前分页限制。
* 安全检查不修改任何译文。
* 中英文界面键集合一致，且 HTML 与脚本引用的每个键都存在。
* 脚本引用的每个元素 `id` 都真实存在于 HTML。

## 三、关键回归覆盖（对照验收项）

* 翻译文件导入 / 导出、原文与译文对应：workflow 用例 + 既有 `cli.e2e.test.mjs`。
* 复制单条 / 批量复制、术语词典与替换、排序、分页、中英文切换：保留原有实现，
  由引擎与 i18n 用例间接覆盖。
* 撤销：单条、批量、导入合并均可撤销。
* 合并 / 迁移：构造了 ID 相同原文相同、ID 相同原文改变、ID 不同原文相同、
  一条原文对应多条、冲突等场景。
* 安全检查：合法语法不误判、变量缺失 / 宏异常可定位、普通标点不产生大量误报、
  检查不修改译文。
* 文件往返：canonical 序列化保证字段顺序稳定；原文、译文、身份字段保持一致。

## 四、数据兼容性结论

* 游戏翻译包格式**未改变**：导出仍为 `manifest.json` + `segments.jsonl` +
  `segments.csv`（以及原包内的其他文件），字段与 `core/src/lib/kit.mjs` 的
  `SEGMENT_CSV_COLUMNS` 一致。
* 编辑器的状态标记、备注、忽略项、可选译文只写入浏览器草稿与独立的
  `*.dolpkit.json` 编辑工程，**不写进游戏翻译包**。
* 旧文件（不含新增元数据）仍可正常导入；编辑工程缺字段按默认值处理。
* 未修改 `core/`、`schemas/`、`runtime/` 的对外接口。

## 五、已知限制与未实现（如实说明）

* 近似（模糊）原文匹配**未实现**；重复原文识别只做**完全一致**的稳定检测，
  这是本轮明确的阶段一范围。迁移中的“近似原文匹配”仅保留为概念，不提供自动
  匹配。
* 浏览器交互测试使用自建的最小 DOM / IndexedDB 桩，而非真实浏览器引擎；
  它能启动真实脚本并驱动主要流程，但**不**验证 CSS 布局与实际渲染。
  受环境网络策略限制，本轮未能用内置浏览器打开本地 `file://` 页面做渲染验证。
* 当条目数超过 30000 时，编辑后的自动分析不再防抖触发，只在显式“检查全部 /
  打开面板 / 使用相关问题筛选”时计算；界面统计中的“安全问题数”会先用 `—`
  占位。
* 可见性可见的“近似匹配 / 语义合并”等增强不在本轮范围。

## 六、手动验收建议

1. 用 Chrome / Edge 打开 `dolp-kit-translation-editor.html`，导入一个
   Toolkit 导出的 Kit，确认原文 / 译文对应正确、分页与排序正常。
2. 修改若干译文，刷新页面，确认弹出草稿恢复三选一，且“恢复草稿”能还原。
3. 复制原文、批量复制、术语替换后，用“撤销 / 重做”验证可作为一组撤销。
4. 打开“安全检查 / 术语检查 / 重复原文 / 冲突”面板，确认能定位到条目且不自动改译文。
5. 用另一份同批译文测试“预览冲突后逐条选择”，确认默认不覆盖。
6. 导出 ZIP 后再导入 Toolkit，确认严格构建通过且游戏翻译包不含任何编辑器字段。
7. 用旧版本已翻译 Kit 测试“迁移新版本译文”，确认改原文的条目未被迁移。

## 七、第二轮：数据安全修复与分页增强

本轮按“先复现、再修复、用测试锁定”的顺序处理了已发现的问题，并补齐分页导航。

### 已修复

| 问题 | 修复 |
| --- | --- |
| 跨版本迁移调用同版本交接校验，导致旧版本 ZIP 被拒 | 拆分为 `validateKitFormat`（任意版本通用：kind + schema 主版本）与 `validateHandoffManifest`（同版本：story / inventory / 语言一致）。迁移改用仅格式校验的 `readTranslatedFile(..., {requireIdentity:false})` |
| 批量复制原文未进入撤销历史 | `copyAllSources()` 改为一条 `applyChanges` 批量记录，一次撤销 / 重做 |
| `commitEntry()` 未更新 `model.seq` / `model.modified`，术语修复、批量标记、工程导入等不触发“存在未导出修改”与草稿保存 | 新增唯一入口 `markDirty()`；`commitEntry()`（除 `count:false` 的逐字编辑收尾外）与撤销 / 重做统一调用，删除了散落的 `model.seq++` |
| `planDuplicateFill()` 在同组多译文时默认取第一种 | 默认跳过歧义组；只有在面板中显式选择某种译文后才填充，并报告跳过数量 |
| 工程导入仅凭 `unitId` 复用校对状态 | 同 Kit 才按 `unitId` 合并；不同 Kit 必须逐条核对工程记录的 `protectedSource` 与当前条目一致，无法确认的记录跳过并报告 |
| 相邻同类问题 | 迁移仅对非空 `protectedSource` 建索引，避免空原文误配；草稿备份也写入 `sources` 以便往返校验 |

### 分页

* 顶部与底部两套导航，共享唯一 `model.page`；`updateFilter()` / `renderList()` 复用。
* 最多 9 个连续页码，居中、两端自动收敛；总页数 < 9 显示全部；当前页高亮；
  保留上一页 / 下一页；数字输入 + 「跳转」按钮，支持 Enter 与范围收敛。
* 翻页前 `commitPendingField()`，翻页后定位到列表顶部（仅在页码变化时滚动）。

### 本轮新增测试（共 10 项）

* 引擎：`pageWindow` 覆盖总页数 1 / 5 / 9 / 10 / 100 与首 / 中 / 末页窗口；
  重复原文歧义组默认跳过、显式选择后可填充；无原文条目不参与按原文匹配。
* 工作流：9 页码窗口 + 两套导航共享状态 + 数字 / 输入 / Enter 跳转 + 越界收敛；
  100 页居中窗口与两端收敛；筛选后跳页且译文不丢、不串位；
  批量复制一次撤销 / 重做；状态改动 / 批量标记 / 术语修复都置“未导出”并触发草稿；
  **真正不同版本**的 Kit ZIP 用于迁移（同版本交接仍拒绝该文件）；
  不同 Kit 的工程状态不被按 `unitId` 复用，同 Kit 仍可导入。

### 结果

`node core/src/selftest.mjs` = `60 passed, 0 failed`；
`node --test "core/test/*.test.mjs"` = `137 passed, 0 failed`；
`node examples/run-example.mjs` 通过。既有断言全部保留，未通过删除断言或放宽
安全约束来使测试变绿。

## 八、第三轮：撤销历史、忽略项安全与草稿备份来源

### 已修复

| 问题 | 修复 |
| --- | --- |
| 单条“复制原文”与“替换关键词”改了译文却不进撤销历史 | 在条目内新增 `recordEdit(label,before,after)`：值更新仍走 `changeTo`（负责脏标记 / 草稿），随后以 `noApply + count:false` 追加一条历史记录，并把 `model.fieldStart` 前移到新值，避免随后的 blur 事件重复记录 |
| 工程导入可能导入不可信的忽略项 | `unitId\u0001term` 忽略键只在条目身份被确认（同 Kit，或工程记录的 `protectedSource` 与当前一致）时才导入；无法验证的忽略项被拒绝并计数。忽略项增删改为历史操作（新增 `applyOps` 的 `ignore` 目标），支持撤销 / 重做 / 草稿 / 未导出状态 |
| 打开 Kit 时导出草稿备份用了尚未提交的旧 `model.segments` / `currentIdentity()` | `exportDraftSnapshot(previous,name,ctx)` 接收 `ctx={manifest,segments,draftKey}`；`loadFile()` 在恢复草稿对话框流程中把**正在导入的** Kit 的 manifest / segments / draftKey 传入，备份的来源身份与 sources 正确 |

### 本轮新增测试（共 6 项）

* 单条复制、术语替换各为一次可撤销 / 重做操作，且 blur 不再重复记录。
* 干净工程（只含忽略项）导入后：忽略项生效、进入历史、置“未导出”、触发草稿。
* 不同 Kit 相同 `unitId`、不同原文：忽略项被拒绝，工程保持未改动。
* 切换 Kit 时导出草稿备份：来源身份与 sources 取自**正在导入**的 Kit。
* 首次打开 Kit（预先存在草稿）时导出草稿备份：来源身份 / projectId / sources 正确。

`node core/src/selftest.mjs` = `60 passed, 0 failed`；

## 九、第四轮：跨 Kit 状态隔离与复制 / 替换焦点

### 已修复

| 问题 | 修复 |
| --- | --- |
| 切换 Kit 时旧项目状态残留 | `loadFile()` 提交新 Kit 时，未恢复草稿则清空 `model.meta`、`model.ignoredTerms`、`model.recoveries`；并**始终**重置只属于上一个 Kit 的临时分析 / 预览状态（`safety`、`termFind`、`dupGroups`、`dupUnits`、`conflictUnits`、`previewConflicts`、`previewChoices`、`previewFill`、`migratePlan`、`fieldStart`、历史）。恢复草稿时 `applyDraft()` 先载入**新 Kit**的记录 / 忽略项 / 恢复点，提交块不会覆盖 |
| 复制 / 替换在列表重建后对已脱离 DOM 的 `textarea` 调 `.focus()` 无效 | 值更新与历史记录不变，新增 `focusById(id)`：重建后按文本域 id 重新取到新节点、聚焦并把光标置于末尾；无法渲染时安全跳过。`recordEdit()` 仍把 `fieldStart` 前移到新值，blur 不会重复记录 |

### 本轮新增测试（共 3 项）

* 切换 Kit：A 的忽略项与恢复点不泄漏到 B；B 的草稿恢复后使用 B 自己的忽略项 / 译文 / 恢复点。
* 编辑中直接点「复制原文」：先记录输入（1 条），再记录复制（1 条），共 2 条不重复；
  焦点回到新的译文框且光标在末尾；继续 blur 不新增；两次撤销 / 重做正确。
* 编辑中直接点「替换关键词」：同上，焦点恢复、单次可撤销。
